MVP do Sistema de gestão de aluno e aulas (PONG)

# Tecnologias
Sistemas web utilizando HTML, CSS, JAVASCRIPT e JQuery
Sem banco de dados no momento
Se trata de um MVP, utilize dados dinâmicos

# Funcionalidades
Este software será utilizado pelo professores. Assim, cada professor que logar deverá visualizar seus dados, alunos, turmas, disciplinas, cursos e unidades operacionais separadamente.
Crie uma tela de login completa com login/senha e esqueci a senha. Também crie um link de cadastro do usuário, deixe os dados isolados a cada usuário.
CRUD de usuários do sistema (professores) com os dados: código(auto incremento), nome, e-mail e telefone, sendo o único dado obrigatório o nome do aluno.
CRUD  de alunos que serão cadastrados pelos professores no sistema, com os dados: nome, matricula, email e telefone.
CRUD das turmas com os dados: Turno, código, curso e unidade educacional
CRUD das disciplinas com os dados associados: alunos,  professor, curso, nome da disciplina, frequência, plano de aula, notas (av1, av2, reposição e final), carga horária e sala.
CRUD dos cursos com os dados: código(auto incremento), nome do curso, nome do coordenador, escolha da unidade educacional
CRUD da unidade educacional: código(auto incremento), Nome da unidade, endereço, cidade, uf(siglas Brasil)
Necessita ter dinâmica no preenchimento dos formulários (buscando os dados de outra tabela)
No registro das frequências das aulas o professor poderá fazer a chamada oral e marcar as opções presença/ausência/justificada para cada aluno, ou poderá gerar um QRCode onde os próprios alunos leiam o QRCOde com um celular e registrem sua presença através de 2FA com seu e-mail cadastrado.
A frequência deverá ser acessada através do plano de aula a ela correspondente. Exemplo: nos planos de aula deve existir um botão de registro de aula, ao clica no botão tenho a opção de registrar a frequência ou cancelar a aula. Ao registrar a frequência o software deve abrir a frequência e o professor realizará através de chamada oral ou pelo QrCode. Quando ele finalizar a chamada da frequência o software deverá registrar a aula como ministrada e manter um histórico da frequência vinculada a aula. Essa frequência deverá se manter acessível para possíveis correções por parte do professor.
Ao salvar a chamado oral o software necessita voltar ao menu anterior das aulas mostrando o novo status daquela aula.

Necessita ter um dashboard completo sobre os dados do sistema.
